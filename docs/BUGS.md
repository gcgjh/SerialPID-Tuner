# BUG 与已知问题清单

状态口径：**已修复**＝本轮验收中定位并改正；**已知问题**＝不阻塞 v0.1 离线闭环，
列入后续迭代；**待确认**＝依赖硬件决策或真机验证，当前无法在主机侧闭环。

## 一、已修复（v0.1 验收阶段）

| 编号 | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| F-01 | MCU `PONG.status` 与 PC 冻结枚举对不上 | 固件按位掩码实现，协议冻结口径为枚举（0 空闲 / 1 运行 / 2 阶跃中） | 改为枚举取值；NVM 故障改走 ERROR 帧上报，不再占用状态位 |
| F-02 | 阶跃事件相位语义与上位机不一致 | 固件 `STEP_EVENT.phase` 取值与 PC `StepPhase` 错位（开始 / 保持结束 / 中止） | 对齐为 0 空闲 / 1 运行中 / 2 完成；中止与手动停止回到空闲 |
| F-03 | fuzz 用例帧计数正确但 type/len/payload 错位 | 黄金向量按构造顺序记录，真帧被随机插入垃圾流后流内顺序已变 | 生成器改为由 PC `FrameDecoder` 回采流内 `(type, payload)` 序列作为真值表，重新生成头文件 |
| F-04 | `pid_app.c` 编译告警：`app_send_type` 静态函数未使用 | 重构后遗留死代码 | 删除该函数，`-Wextra` 下零告警 |
| F-05 | 断流后接收线程不退出：TCP 对端关闭后 `read` 立即返回空字节，空闲超时分支只标记断开、通知上层却不跳出循环，线程忙等烧满一个核；串口路径退化为僵尸线程，每断一次泄漏一个；旧线程收尾还会关掉被重连覆盖的新传输，表现为“刚连上就断”且日志无因 | 超时分支把循环唯一出口堵死；线程回读共享 `self._transport` 造成生命周期错配；连接状态跨线程读写无锁 | 传输对象按参数传入线程，线程只操作本地引用；超时 / 读异常 / 写异常统一走“标记状态 → 通知上层 → 退出循环”；空读计数 + 20ms 节流兜底；收尾先做身份比较，仅当共享字段仍指向自己这份传输才关闭；连接状态加锁；空闲阈值对齐文档 1s；不做自动重连。二轮复核（card5）：`test_comm_disconnect.py` 3 用例通过——超时掉线后线程退出、进程 CPU < 0.2s、5 次重连无线程增长、旧线程不误关新连接，未复现空转 |

## 二、已知问题（不阻塞当前版本）

| 编号 | 级别 | 现象 / 限制 | 影响 | 计划 |
| --- | --- | --- | --- | --- |
| B-01 | 低 | `PONG.status` 不会返回 IDLE：`app_status()` 仅在「运行 / 阶跃中」之间取值，上电即 RUNNING，手动停止 / 中止后也回到 RUNNING | 上位机无法通过心跳区分「未使能 / 脱机」与「已使能运行」；协议枚举里的 IDLE 暂无产生路径 | v0.2 明确 IDLE 产品语义（脱机 / 手动停止 / 未使能）后补状态转换 |
| B-02 | 低 | `docs/wiring.md` 已补齐并与 `user_guide.md` 互链；当前按默认 USART1（PA9/PA10）给通用接线表，具体引脚 / 传感器 / 执行器仍待硬件方案确认 | 换用非 USART1 或其它型号时需按实际引脚核对表内映射 | 硬件选型拍板后回填实物引脚、通道与标定值 |
| B-03 | 文档 | `docs/ITERATION.md` 勾选状态滞后：通信层 / GUI / 模拟器等已完成项仍标未完成 | 路线图与实际进度不符 | 本轮已同步勾选；后续每轮迭代同步更新 |
| B-04 | 工程化 | `.gitignore` 与文档曾按「工作区保留 `SerialPID-Tuner.spec`」维护：忽略规则带着相关注释，五份文档把它写成与一键脚本等价的构建入口。实际该文件从未入库，打包完全由 `scripts/build.bat` / `build.sh` 的命令行参数驱动 | 文档给出的 `pyinstaller SerialPID-Tuner.spec` 命令首步即失败，读者容易误判成「仓库漏文件」，甚至自行补一份 spec 造成二次污染 | 已修正（card6，2026-11-07）：删除失效注释，改为按构建副产物忽略 `*.spec`；五份文档统一为「不以 spec 作为构建入口」。命令行构建仍会在工作目录生成同名 spec 副产物，不入库 |
| B-05 | 功能缺口 | 预设管理已接入参数面板（保存 / 加载 / 删除 / 重命名；加载只填界面、不自动下发，card13）。**链路质量统计已补齐**（`link_stats.py` + 状态栏质量灯，card28：按坏帧率 / 丢帧率 / RTT 抖动 / 心跳欠账判绿黄红）。尚未接入 GUI 的有：曲线缩放复位、多曲线显隐切换、错误日志落盘。曲线暂停 / 继续、时间窗下拉、纵轴自动已在绘图面板接入 | v0.2 其余体验项不可用；不影响基础调参闭环 | v0.2 迭代 |
| B-06 | 测试口径 | 离线模拟器是简化一阶惯性植物 + 简易 PID，非线性、滞后、噪声、饱和均未建模 | 模拟器上的整定参数不能直接当作真实对象的可用参数 | v0.3 真机联调以实物曲线为准 |
| B-07 | 功能缺口 | `PID_ACK` 仍无独立应答超时定时器：命令是否被接受以实际收到的应答帧为准。**链路级看门狗已补齐**（card28）：PC 每 1.0 s 主动发 `PING`，连续 3 次无 `PONG` 且同窗口无任何帧才判 `heartbeat-timeout`；`PID_ACK` 单帧级别的应答超时仍未实现 | 固件不执行命令且不回 ACK 时，界面不会单独报「应答超时」，只能靠心跳判死或人工从曲线看出没动作 | 保留观察：心跳已覆盖"链路是否活着"，命令级超时待真机联调后再决定是否需要 |

## 四、card3 界面缺陷（已修复，2026-11-05）

| 编号 | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| F-06 | 畸形帧让主界面静默停更（曲线冻结、无任何提示） | 槽函数直接按类型解包、无载荷长度预检；通信层异常保护只包住“投递信号”，真正解析在主线程事件循环、异常在保护圈外只进 stderr | 解析前按帧类型长度预检（`protocol.payload_error_reason`，数值与 PROTOCOL.md §4 / `PAYLOAD_FMT` 同源，不另抄表）；槽函数外层 try/except 兜底；状态栏常驻“解析异常 N”；ERROR 帧校验声明 msg_len vs 载荷实际长度，不匹配按截断处理、不越界读 |
| F-07 | 增益 0–100、SP ±1000 写死在界面 | 参数范围被当作界面细节而非产品配置；旧配置文件未读取 | 新增 `config.py`：范围抽成 `config.json`（`%APPDATA%/SerialPID-Tuner/`，`SERIALPID_CONFIG` 可覆盖），界面按配置生成上下限；下发前数值有限性校验（NaN/Inf/float32）原样保留，防线未拆 |
| F-08 | 未识别帧逐条刷日志，正常信息被顶掉 | 无聚合策略 | 新增 `frame_log.UnknownFrameLogger`：按类型计数，首次一行完整信息，之后每满 100 次或每满 5 秒汇总一行（1000 个未知帧约 10 行 <15 行） |
