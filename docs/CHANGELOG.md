### 新增（卡33）

- **帧日志对话框五列列表**（`gui/frame_log_dialog.py` 重写）：`QTableView` + 自定义
  `QAbstractTableModel` 五列「时刻 / 方向 / 类型 / 长度 / 载荷摘要」，虚拟化绘制
  （8000 帧刷新 < 0.5 s，滚动不卡）；载荷摘要按前 8 字节出十六进制并标总长
  （`64 00 00 00 00 00 E0 41 …（共 20B）`），悬停给完整 `describe()`；发送 / 接收
  两色区分。列表下方保留一块 96 px 高的消息区，专门给导出结果与坏行提示。
- **回放菜单入口**（`工具 → 回放帧记录…`）：选一个 JSONL 就直接按原时序驱动界面。
  与「帧日志 / 回放…」的区别是不先摊开列表，适合别人发来一份帧流时立刻看现场；
  回放前先断开实时连接，整个重演只读，不会把历史 rx 帧当成命令再下发。
- **断开时的导出提示**：任何断线（含故障注入强制断线）都会在现象 / 下一步之后
  多一行"帧日志可从「工具 → 帧日志 / 回放」导出（JSONL 能直接发给别人），或
  「工具 → 回放帧记录」重演；当前缓冲 N 帧还没保存"——断开的这一刻最该留住的是证据。
- **仿真面板故障注入折叠区**（`gui/fault_panel.py`）：丢帧率（设备→上位机，
  0–50%）、坏帧率（CRC 损坏，0–30%）、N 秒后强制断线（0–60 s，0 = 不断）三根滑杆，
  **默认全零**且默认折叠；默认零时劣化层整体直通（不丢字节、不起后台线程）。
  只注入下行：上行命令也丢会让"参数没生效"与"链路坏了"分不清。
- **倍速与单步**：0.5× / 1× / 2× / 4× / 10×（卡面点名的 0.5 / 1 / 4 都在），
  另有暂停 / 继续与逐帧步进，进度按 `已放 / 已结束` 给出。

### 变更

- **帧日志 JSONL 每行含七键**：`t`（相对时间戳 ms）、`dir`（`rx`/`tx`）、`dir_label`
  （`接收`/`发送`）、`type`、`name`、`len`、`payload`（十六进制）。仍不含端口号、
  文件路径与序列号——这份文件可以原样发给别人。
- **方向别名折叠**：读回时 `up→tx`、`down→rx`（另含 `in/recv/下行/out/send/上行`），
  所以 `sim/recorder.py` 录的 `dir=up/down` + 整帧 `raw` 也能被界面直接打开；
  写出的文件仍统一 `rx/tx` + `dir_label`，两套文件都读得进来，用户不必记哪个格式属于哪个工具。
- **坏行双路径**：`load_jsonl()` 保持严格（抛 `ValueError` 带行号，用来判断"这份文件
  能不能完整回放"）；界面读外部文件改走 `load_jsonl_lenient()`——坏行跳过、条数与
  行号都进三段式提示，其余帧照常回放。
- **大文件导出前先问体积**：估算 UTF-8 体积超过 256 KB 时弹确认框，取消不落半份文件。

### 新增

- **主动心跳**：PC 每 1.0 s 发 `PING`，用 `PONG` 到达算往返时延（FIFO 结账，避免把刚发的
  PING 当基准把 RTT 算成 0）。判死条件是"连续 3 次无 PONG **且**同窗口没有任何帧"——
  "固件忙到没回 PONG 但仍在发遥测"只降级为质量提示，不判死。心跳间隔 / 次数 /
  兜底窗口 / 帧日志容量可在 `config.json` 的 `comm` 段配置；`heartbeat_interval_s = 0`
  退回到纯空闲断流判定，库默认仍是关闭（不干扰纯逻辑测试）。
- **链路质量统计**（`link_stats.py`）：收 / 发 / 坏帧 / 约丢帧计数、窗口帧率、字节速率、
  RTT 均值 · 最大 · 抖动、心跳欠账、会话时长，按 坏帧 > 丢帧 > 坏帧存在 > 丢帧 >
  心跳欠账 > 抖动 > 帧率跌落 的优先级判 绿 / 黄 / 红。丢帧按设备 u32 时间戳间隔推算：
  差值 ≥ 2³¹ 判为设备复位（只挪基准、不计丢帧），计数器回绕按模运算继续。
- **状态栏质量指示**（`gui/link_status.py`）：一个灯 + 帧率 / RTT / 约丢三个数字，1 Hz 刷新；
  悬停给出完整统计与口径（"约丢"是推断值不是精确计数），坏帧计数仍在右侧。
- **ERROR 码中文化**（`protocol.py`）：`ERROR_CATALOG` 与固件 `pid_err_code_t` 逐项对齐
  （`0x00`–`0x06`），日志输出"数字 + 含义 + 固件原话 + 建议动作"；表外码显示
  "未定义的错误码 0xNN"并保留原话，不做猜测。
- **断线原因分类**（`comm.py`）：八类原因常量（`timeout` / `heartbeat-timeout` /
  `peer-closed` / `device-removed` / `driver-error` / `write-error` / `read-error` /
  `closed`），每类配"现象 + 下一步"两段中文；串口异常按关键字归类（拒绝访问 / 拔出 →
  `device-removed`，ClearComm / 句柄 → `driver-error`）。旧 `timeout` 串保持不变。
- **可选自动重连**：默认关闭；开启后按 1 / 2 / 5 / 10 s、之后每分钟重试，最多 7 次，
  状态栏显示"第 N 次，X s 后"，成功 / 失败 / 放弃都写日志。默认关的理由：静默重连会把
  "设备掉线"伪装成"一直连不上"，调试时最需要看见的就是掉线。
- **帧级日志与回放**（`frame_trace.py` + `gui/frame_log_dialog.py`）：2000 帧环形缓冲
  （超出丢最旧并计入"已滚出"）；导出文本（给人看）与 JSONL（一行一帧：
  `t/dir/dir_label/type/name/len/payload`，不含端口号与路径）；读回时严格模式坏行
  **抛 ValueError 带行号**，界面读外部文件走宽容模式（跳过坏行并计数提示，card33）；
  回放只放 rx 帧，支持 0.5× / 1× / 2× / 4× / 10× 倍速、暂停与单步，基准取第一条帧。

### 变更

- `TcpTransport.read` 区分"对端 FIN"与"读超时"：新增 `PeerClosed`。此前 `recv()` 返回空字节
  与超时一样返回 `b""`，"对端程序正常退出"会被误报成"链路超时"；其它 `OSError` 统一包成
  `OSError("TCP 读失败: …")` 交由通信层归类。
- 日志里的 `ERROR code=N msg=…` 改为中文可读行（含义 / 固件原话 / 建议）。
- `PONG` 不再每秒刷一行日志（心跳 1 Hz 下会淹没现场）：只记"第一次通"与"状态变化"。
