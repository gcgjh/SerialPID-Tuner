# 功能 — 文档对照清单（0.2.1）

> 用途：回答"这个功能写进文档了吗、写在哪、是不是过时"。出下一批任务卡时，
> 先看表里的「缺失 / 过时」，不要凭印象判断功能存不存在。
>
> 状态只取三种：**已写**（文档说清了入口与行为）、**缺失**（文档没提）、
> **过时**（提到但与当前实现不符）。三份主文档指 `README.md`、
> `docs/user_guide.md`、`docs/CHANGELOG.md`。
>
> 核对方式：从代码取证（`gui/` 下控件与菜单、`tools/` 下脚本 docstring），
> 不沿用旧摘要。核对日期 2026-11-07。

## 四、结论：下一批该补什么

1. **优先补「缺失」且用户天天会碰的**：场景预设（README / 手册）、链路设置
   对话框、参数预设管理、启动自检（README）。
2. **「过时」只有一处但会误导**：CHANGELOG 的「5 预设」必须改成 8 个，否则
   下一批会以为三个新场景没实现。
3. **工具类不必都进手册正文**：`sweep_params` / `pressure_test` /
   `bringup_check` 更适合进 README 的「工具」小节 + 各自文档，手册只留
   用户会用的入口（扫参可在整定流程里提一句）。
4. **真机内容**（H750 工程、bringup 八步、首联脚本）面向的是"有板子的人"，
   放 README 一句指路 + `docs/bringup.md`，不要塞进用户手册主线。
