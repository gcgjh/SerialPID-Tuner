# SerialPID-Tuner 串口协议基准（冻结版 v1.0）

> 本文件是 PC 上位机与 STM32 固件之间的**唯一接口基准**。所有角色必须按本文件实现，
> 包类型编号、字段顺序、字节序、CRC 算法不得私自改动；确需变更须升版本号并双方同步。

## 1. 物理层

| 项 | 取值 |
| --- | --- |
| 总线 | UART（3.3V TTL，USB 转串口） |
| 波特率 | 115200 |
| 数据位 | 8 |
| 校验位 | None |
| 停止位 | 1 |
| 流控 | 无 |

## 2. 帧布局

```
┌──────┬──────┬──────┬──────┬─────────────┬──────────┬──────────────┐
│ SOF0 │ SOF1 │ LEN  │ TYPE │  PAYLOAD    │ CRC16    │    EOF       │
│ 0xAA │ 0x55 │ u8   │ u8   │  N 字节     │ u16 LE   │ 0x77 × 4     │
└──────┴──────┴──────┴──────┴─────────────┴──────────┴──────────────┘
```

| 偏移 | 字段 | 长度 | 说明 |
| --- | --- | --- | --- |
| 0 | SOF0 | 1 | 固定 `0xAA` |
| 1 | SOF1 | 1 | 固定 `0x55` |
| 2 | LEN | 1 | PAYLOAD 字节数 N（0 ≤ N ≤ 250） |
| 3 | TYPE | 1 | 包类型，见第 4 节 |
| 4 … 3+N | PAYLOAD | N | 字段按第 4 节顺序排列 |
| 4+N | CRC_LO | 1 | CRC16 低字节（小端） |
| 5+N | CRC_HI | 1 | CRC16 高字节（小端） |
| 6+N … 9+N | EOF | 4 | 固定 `0x77 0x77 0x77 0x77` |

### 2.1 数值编码

- 多字节整数一律**小端序**（Little-Endian）。
- 浮点一律 **IEEE-754 单精度 float32 小端**。
- 时间戳单位为毫秒（u32，MCU 上电起算，溢出回绕由接收方按差值处理）。

### 2.2 CRC16-Modbus

- 多项式：`0xA001`（反射多项式，对应正向 `0x8005`）
- 初值：`0xFFFF`
- 输入/输出：不额外异或；结果直接小端附加。
- **校验范围**：`LEN + TYPE + PAYLOAD`（不含帧头、不含帧尾）。

参考实现（C / Python 同构）：

```c
uint16_t crc16_modbus(const uint8_t *data, uint16_t len) {
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (int b = 0; b < 8; b++) {
            if (crc & 0x0001) crc = (crc >> 1) ^ 0xA001;
            else               crc >>= 1;
        }
    }
    return crc;
}
```

标准校验向量：`crc16_modbus("123456789") == 0x4B37`。

## 3. 收发与错误处理

1. 接收方以流式字节喂入解包器，自动处理粘包、拆包。
2. 帧头失配：逐字节丢弃，重新扫描 `0xAA 0x55`。
3. 帧尾失配：丢弃当前首字节，重新找帧头。
4. CRC 失配：丢弃整帧并重同步，**不得**把错误载荷交给上层。
5. 未知 TYPE：保留载荷但不响应，记录调试日志。
6. 单帧 LEN 超过缓冲上限（250）：丢弃整帧并上报告警。
7. 命令-应答：`PID_ACK` 是否被接受以实际收到的应答帧为准，PC 侧**仍不**对 `PID_ACK` 设独立超时定时器；链路存活由 **主动心跳**判定（PC 每 1.0 s 发 `PING`，连续 3 次无 `PONG` **且**同窗口内没有任何数据才判链路失效），空闲断流 1.0 s 保留为兜底判据（见 4.1）。心跳复用已冻结的 `0x01/0x02`，帧格式不变。

## 4. 包类型定义（冻结）

| TYPE | 名称 | 方向 | PAYLOAD 布局 |
| --- | --- | --- | --- |
| `0x01` | PING | PC→MCU | 空 |
| `0x02` | PONG | MCU→PC | `fw_ver u8`，`status u8`（0=空闲，1=运行，2=阶跃中） |
| `0x10` | PID_SET | PC→MCU | `Kp f32`，`Ki f32`，`Kd f32`，`SP f32` |
| `0x11` | PID_ACK | MCU→PC | 回显 `Kp f32`，`Ki f32`，`Kd f32`，`SP f32`，`result u8`（0=接受，1=越界拒绝） |
| `0x12` | SP_SET | PC→MCU | `SP f32` |
| `0x20` | TELEMETRY | MCU→PC | `t_ms u32`，`SP f32`，`PV f32`，`OUT f32`，`err f32` |
| `0x30` | STEP_START | PC→MCU | `amplitude f32`，`hold_ms u32` |
| `0x31` | STEP_STOP | PC→MCU | 空 |
| `0x32` | STEP_EVENT | MCU→PC | `phase u8`（0=空闲，1=运行中，2=完成），`t_ms u32` |
| `0x70` | ERROR | MCU→PC | `code u8`，`msg_len u8`，`msg ASCII`（UTF-8/ASCII，不含结束符） |
| `0x71` | RESET | PC→MCU | 空，MCU 软复位 |

### 4.1 遥测周期与链路存活判定

- MCU 按控制周期上报 `0x20`，默认 20 Hz（50 ms），可在固件 `mcu/Inc/pid_app.h` 的 `PID_TELEMETRY_PERIOD_MS` 宏调整。
- PC 绘图以 `t_ms` 为横轴；设备复位导致 `t_ms` 归零时重新起算，**不计**丢帧。
- **主动心跳**：PC 每 1.0 s 发一帧 `PING`（`0x01`），用 `PONG`（`0x02`）的到达算一次往返时延（RTT）。间隔与容错次数可在配置文件 `comm.heartbeat_interval_s` / `comm.heartbeat_max_missed` 调整，`heartbeat_interval_s = 0` 表示关闭心跳。
- **判死条件**（两条必须同时成立）：连续 `heartbeat_max_missed` 次 `PING` 没有 `PONG`，**且**这段时间内没有收到任何帧。这样"固件忙到没回 PONG 但仍在发遥测"不会被误判成掉线，只降级为质量提示。
- **兜底**：心跳关闭时，空闲断流超过 1.0 s 视为链路丢失（与旧版行为一致）。默认开启心跳时兜底窗口自动放宽为 `间隔 × 次数 + 1 s`，保证先给出"心跳超时"这种可解释的原因。
- 判死窗口内收到的 `PONG` 会结清全部欠账；RTT 取最早一笔未结账的 `PING` 计算，避免把"刚发出去的 PING"当基准而把 RTT 算成 0。

### 4.2 ERROR 码表（`code u8`）

与固件 `mcu/Inc/pid_comm.h` 的 `pid_err_code_t` 逐项对齐；上位机按此表把数字翻成中文含义与下一步动作。

| code | 名称 | 含义 | 上位机建议动作 |
| --- | --- | --- | --- |
| `0x00` | `PID_ERR_NONE` | 无错误（良性提示） | 无需处理；频繁出现请上报日志 |
| `0x01` | `PID_ERR_PARAM` | 参数非法（NaN / Inf / 越界），本次下发被拒绝 | 检查 Kp / Ki / Kd / SP 范围，旧参数仍在运行 |
| `0x02` | `PID_ERR_PAYLOAD` | 载荷长度与该包类型不符，本帧被丢弃 | 多半是协议版本不一致，确认双方都是 v1.0 后重连 |
| `0x03` | `PID_ERR_TYPE` | 固件不认识这个包类型 | 固件比上位机旧：升级固件或改用已支持的按钮 |
| `0x04` | `PID_ERR_NVM` | 参数写 Flash 失败，掉电不保留 | 本次已生效但重启会丢；查写保护 / 空间后重下发 |
| `0x05` | `PID_ERR_STEP` | 阶跃参数非法或控制器正忙 | 把幅值 / 保持时间调回合理区间，等当前阶跃结束 |
| `0x06` | `PID_ERR_INTERNAL` | 固件内部错误 | 先软复位（`0x71`）再试；仍复现请附版本与步骤 |

> 表外的 `code` 由上位机显示为"未定义的错误码 0xNN"，并保留固件原话，不做猜测。

## 5. 对齐测试向量（双方必须复现）

> 本节 CRC 整数值一律按帧内两字节**小端**解读；数值与字节序列冲突时以字节序列为准
> （已用逐位 CRC 独立复核）。

### 5.1 PING（空载荷）

```
AA 55 00 01 C0 70 77 77 77 77
```

- 校验范围 `00 01`，CRC16 = `0x70C0`（小端字节 `C0 70`）。

### 5.2 TELEMETRY（t=1000 ms，SP=25.0，PV=24.5，OUT=60.0，err=-0.5）

```
AA 55 14 20 E8 03 00 00 00 00 C8 41 00 00 C4 41 00 00 70 42 00 00 00 BF 64 90 77 77 77 77
```

- LEN = `0x14`（20）；CRC16 = `0x9064`（小端字节 `64 90`）。
- 载荷解析：`u32=1000`，`f32=25.0`，`f32=24.5`，`f32=60.0`，`f32=-0.5`。

### 5.3 PID_SET（Kp=2.0，Ki=0.5，Kd=0.1，SP=30.0）

```
AA 55 10 10 00 00 00 40 00 00 00 3F CD CC CC 3D 00 00 F0 41 AA 29 77 77 77 77
```

- LEN = `0x10`（16）；CRC16 = `0x29AA`（小端字节 `AA 29`）。

## 6. 版本兼容

### 6.1 `fw_ver` 编码

`PONG.fw_ver` 是一个 u8：**高 4 位主版本，低 4 位次版本**。

```
fw_ver = ((major & 0x0F) << 4) | (minor & 0x0F)
```

- 主版本（0–15）：**不兼容**变化的标志（帧布局、字段顺序、字段长度、CRC 范围）。
- 次版本（0–15）：向后兼容的新增（新包类型、新可选字段、旧字段语义扩展）。
- **补丁号不进 `fw_ver`**：u8 放不下三段，补丁只在 CHANGELOG 与"关于"对话框里体现。
- 任一字段超过 15 都必须改协议字段（u8 → u16 或拆成两个字节），**不得截断溢出**。

### 6.2 与仓库 tag 的对应

| 仓库 tag | `fw_ver` | 协议基准 | 说明 |
| --- | --- | --- | --- |
| `v0.1.0` | `0x01` | v1.0 | 上一版 |
| `v0.2.0` | `0x02` | v1.0 | 当前基线（固件 `PID_FW_VERSION=2`） |
| `v1.0.0` | `0x10` | v1.0 | 协议冻结、对外可用 |
| `v1.2.3` | `0x12` | v1.0 | 补丁号 3 不进 `fw_ver` |
| `v2.0.0` | `0x20` | v2.0 | 不兼容变更，协议主版本同步 +1 |

两套版本号不要混：

- **协议基准版本**（本文档标题里的 v1.0）只在帧定义变化时升；
- **程序版本**（git tag / `fw_ver`）每次发布升，其中主版本必须与协议主版本同步——
  协议发生不兼容变化时，程序主版本 +1，`fw_ver` 的高 4 位跟着变。

### 6.3 唯一真相与同步义务

| 位置 | 角色 |
| --- | --- |
| `mcu/Inc/pid_app.h` 的 `PID_FW_VERSION` | **固件侧唯一真相**，直接填进 `PONG.fw_ver` |
| `git tag` | 发布标识，必须与 `fw_ver` 的 4+4 解一致 |
| `CHANGELOG.md` 最高版本 | 人读的记录，必须一致 |
| PC 侧 `__version__` | 上位机版本，与 tag 一致（与 `fw_ver` 同源，不单独维护） |

任一处改动都必须同步其余三处，写进发布检查清单（`docs/RELEASE_CHECKLIST.md`）。
"关于"对话框、exe 文件属性里看到的主/次版本，应当能从 `fw_ver` 反推出来。

### 6.4 接收方的处理

- PC 侧解析出主/次版本后，**主版本不一致时弹告警但不阻断连接**——能连上但可能对不上的
  组合（例如固件 0.2 + 上位机 0.1）比直接拒绝更有用：用户至少能看到曲线，再决定要不要升级。
- 次版本不一致不告警：按向后兼容处理。
- 固件侧不校验 PC 版本，也不因版本不匹配改变任何行为。

- 本基准对应协议版本 **v1.0**；当前程序版本 `v0.2.0` → `fw_ver = 0x02`。
